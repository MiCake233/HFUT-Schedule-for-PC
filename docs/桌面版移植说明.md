## 2. 架构

```
:app  (Kotlin Multiplatform library)
├─ commonMain        资源(Compose Resources)、共享模型
├─ jvmShared    ★     Android 与 JVM 同时 dependsOn 的中间源集，原 Android 源码绝大多数在此
├─ androidMain        Android 专属：Activity/WebView/相机/小组件/通知/快捷方式…
└─ jvmMain            桌面专属：Skia 图片解码、AWT 浏览器、.ics 导出、空实现的权限
:androidApp           Android 应用壳（applicationId 仍是 com.hfut.schedule）
:desktopApp           Windows 壳：窗口、主题、MSI 打包
```

### 2.1 平台边界（三种机制）

1. **expect/actual 能力对象**：`Platform`、`AppCapabilities`（含 `saveAndShareTextFile`、
   `supportsProgressiveBlur`、`openOperation`、`cleanCache`…）、`PermissionSet`、
   `PlatformStarter`、`OcrSupport`、`ClipBoardHelper`、`CalendarWriter`、
   `LanguageHelper`、`loadImageBitmap`/`pickColorFromTop`。
2. **类型化页面注册表**：`RenderPlatformDestination(destination)` —— 共享 Destination
   把 `Content()` 委派给它；Android 用 `when (destination)` 类型分发调用真实界面
   （参数随 Destination 对象走），桌面返回 false 由占位兜底。
3. **组件槽位**：`UiSlots.register/render/action/updateChecker` —— 共享页面里的
   Android 专属子组件（电费、淋浴、课表设置面板、设置页、上课提醒…）在
   `MyApplication` 注册；桌面端可注册替代实现（`home_settings` → 桌面版设置页），
   没注册就显示占位提示。

### 2.2 桌面端入口

`desktopApp/src/main/kotlin/com/hfut/schedule/desktop/`

* `Main.kt` —— `main()`：注入 `AppInfo`、窗口尺寸/位置记忆（`java.util.prefs`）、
  `--snapshot` 离屏渲染、`--verify-ics` 导出自检
* `DesktopApp.kt` —— 主题（material-kolor 动态取色）+ `MainHost`（SharedNav 导航/转场）
  + 窗口级钩子（登录成功 / 退出）+ 注册 `home_settings` 槽位 + UI 启动自检标记
* `DesktopRoot.kt` —— 根 Destination：协议页 → 登录页 → `HomeDestination`（=MainScreen）
* `DesktopSettings.kt` —— 桌面版「选项」页（版本/外观/WebVPN/协议）
* `icons/app.ico` —— 由 `.idea/icon.png` 转出的多尺寸图标（安装包与快捷方式用）

## 4. 踩过的坑（避免重复）

1. **Gradle wrapper SSL PKIX**：本机 `github.com` 被 Steam++ 代理劫持，证书不可信 →
   换腾讯镜像 + 把代理根证书导入独立信任库（`tools\truststore\jdk-trust.p12`）。
2. **Compose 版本**：CMP 1.12.x 要 AGP 9.1 + compileSdk 37 → 降到 **CMP 1.11.1**；
   `lifecycle` 2.10.0（2.11 需要 compileSdk 37）。
3. **haze 1.6.2 桌面版**的 skia 着色器与 CMP 1.11 `ShaderBrush` 签名不兼容
   （`HazeProgressive` 抛 `NoSuchMethodError`）→ 能力位 `supportsProgressiveBlur()`，
   桌面关掉渐进模糊、用渐变叠加等价实现。
4. **savedstate 双包冲突**（同包名两套 API）→ JetBrains navigation 升到 **2.9.2**。
5. **AVD 静态化**缺 `xmlns:android` → 桌面解析抛 `SAXParseException`，补命名空间。
6. **离屏渲染必须在 AWT 事件线程**（`LiveData.addObserver` 要求主线程）→
   `SwingUtilities.invokeAndWait`。
7. **MSI 打包**的 WiX 从 github 下载被代理拦成 502 → 镜像下载后解压到 `tools\wix311`，
   设 `WIX_PATH` 即可离线打包。
8. **jpackage 内置 JRE 缺模块导致启动崩溃**：`java/sql/Time` NoClassDefFoundError
   → `nativeDistributions.modules(...)` 显式加入 `java.sql`/`jdk.unsupported`/
   `jdk.crypto.ec`/`java.prefs` 等。**验证必须看 UI 是否真的画出来，不能只看进程存活**
   （现在用 `%TEMP%\hfut-desktop-started.txt` 标记 + 截屏双重确认）。
9. **平台注册表不能靠字符串传参**：早期 key 携带参数的方案丢了参数解析，
   Android 端 65 个页面全退化 → 改类型分发。
10. **JDK 21 下的 JVM 目标一致性**：工具链换成 JDK 21 后，Java 编译任务默认产出 21
   字节码，与 Kotlin 的 `jvmTarget=17` 冲突（`Inconsistent JVM Target Compatibility`）
   → 在根 `build.gradle.kts` 里给非 Android 的 `JavaCompile` 任务统一
   `options.release = 17`（Android 任务仍由 AGP 的 compileOptions 控制）。

## 6. 2026-10 修复：CAS 登录一直转圈（1.0.1）

**现象**：输入学号、密码，点「登录」后一直转圈，进不去，也没有错误提示。

**根因**：`SharedPrefs` 里其实有两个 store：

| 名字 | 文件 | 用途 |
| --- | --- | --- |
| `prefs` | `<packageName>_preferences` | 登录页从这里读 `LOGIN_FLAVORING` |
| `saved` | `saveString()` 写入的 store | 拦截器等处写 cookie |

Android 上 `saved` 原本是 `PreferenceManager.getDefaultSharedPreferences(context)`，
它返回的文件名恰好就是 `<packageName>_preferences`，所以两个名字背后**是同一个文件**。
桌面端移植时按字面意思另建了 `_default` 文件，于是链路断在第一步：

1. `AesKeyInterceptor` 把 CAS 返回的 `LOGIN_FLAVORING` 写进 A 文件；
2. 登录页从 B 文件读，得到空串；
3. `CryptoUtil.encryptAES(password, "")` 返回 null；
4. `outputAES?.let { vm.login(...) }` 静默跳过 —— **登录请求根本没发出去**；
5. 但 `loginClick` 已经把 `loading` 置 true 并挂上了结果观察者，
   永远等不到 `code` 回调 → 界面一直转圈。

**修复**：`saved` 与 `prefs` 指向同一个文件；启动时把旧的 `_default` 文件里
已写入的键一次性迁移过来（只补缺失的键，不覆盖）。

**顺带修掉的两个问题**：

* 迁移代码最初在 `prefs` 的 lazy 初始化里又去读 `prefs`，会递归初始化，
  把 `LogUtil` 的类初始化带崩（`NoClassDefFoundError: Could not initialize class …LogUtil`），
  导致 OkHttp 回调线程里抛错。现在迁移通过参数传入目标 store，不再重入。
* 登录失败提示原来是「密码错误」，CAS 当前 `needCaptcha=true`，
  验证码错也会返回 401，容易误导 → 改成「账号、密码或验证码不正确」；
  桌面端也不再显示「点击下载模型文件以启用自动填充」（PC 不做 OCR）。

**验证**（`:desktopApp:loginProbe`，真机联网跑出来的输出）：

```
MAIN_DISPATCHER_OK=true
getKey() -> null
jSessionId = Success(CasGetFlavorSessionDto(needCaptcha=true, jSession=JSESSIONID=...))
getCookie() -> null
executionAndSession = Success((e1s1, SESSION=...))
prefs(LOGIN_FLAVORING) = [ofxn2br3dhipveop]  len=16     <- 修复前是空串
captcha fetch -> status=200 type=image/jpeg bytes=1864 decode=100x45
encryptAES(with cookie) = ok(len=24)                    <- 修复前是 null
login callback code = 401                               <- 假账号的预期结果，说明请求真的发出并有回调
LOGIN_CALLBACK_RECEIVED=true                            <- 转圈会停
```

另外用 `:desktopApp:run` 跑真实窗口时，日志里能看到验证码图片被真正解码并绘制
（`[imgui] draw bitmap 100x45`），所以验证码在桌面上是能显示的，需要手输。

**版本**：`packageVersion` 从 1.0.0 升到 **1.0.1**（同 UpgradeCode，可直接覆盖升级）。
